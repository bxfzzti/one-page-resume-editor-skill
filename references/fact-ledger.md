# 事实底稿

在任何诊断、整理或定制前，先把用户材料拆成事实条目。事实底稿是所有版本的唯一来源。

## 状态

| 状态 | 含义 | 是否可进入最终简历 |
|---|---|---|
| 已确认 | 原文或用户明确回答支持 | 可以 |
| 待确认 | 可能影响结论，但材料不足 | 不可以，先追问 |
| 原文缺失 | 常见信息在原文中不存在 | 不可以补充 |
| 不建议使用 | 重复、无关或无法解释 | 只能在记录后删除、降级、合并或移入风险清单 |

每条事实记录来源位置、候选人的贡献边界、数据口径和可追问点。模型推断不能作为已确认事实。

## 标准字段

事实底稿至少包含以下字段：

| 字段 | 说明 |
|---|---|
| 原文摘录 | 用户原文中的对应句子或短语 |
| 来源位置 | 简历模块、JD 段落或用户补充回答 |
| 事实类型 | 时间、公司、岗位、项目、职责、动作、结果、技能、黑话、缺失项等 |
| 事实状态 | 已确认、待确认、原文缺失或不建议使用 |
| 贡献边界 | 个人负责、牵头、参与、协同、团队结果或无法归因 |
| 数据口径 | 基线、周期、分母、统计范围和是否为估算 |
| 处理方式 | 保留、重排、合并、降级、删除、移入风险清单或追问 |
| 是否进入正文 | 是、否或待确认后决定 |
| 风险或追问 | 需要用户解释或面试可能被追问的问题 |

## 硬规则

- 原文数字、时间、金额、比例、规模、公司名、岗位名、项目名、专有名词和内部黑话不得自行改写。
- 可以调整顺序、合并同一事实、压缩句子，但不能改变事实含义。
- “参与、协同、推动、牵头、负责、主导”按用户实际贡献选择，不因“写得高级”而升级。
- 团队结果必须说明团队或协作者边界；无法归因时保留风险提示。
- 黑话不理解时原样保留并提出确认问题；不能凭上下文猜测后换成通俗词。

## 候选正文来源门禁

生成简历正文前，为每条候选句标注对应事实编号，并分别核对动作、对象、贡献动词和结果。只有原文明确支持或用户明确确认的内容可以进入正文。

- 不把常识、目的或可能收益写成已经发生的结果。原文没有证明时，“提升效率”“提高一致性”“提供数据依据”“推动机制落地”等表达必须删除或移入待确认。
- 贡献动词只能保持原强度或降级。“参与、协同、支持”不得改成“推动、牵头、负责、主导”。同一句包含多个动作时，每个动作分别核对。
- 待确认内容可以进入事实底稿、证据映射、追问和风险清单，不能因为在括号中注明“待确认”就进入最终简历正文。
- 无法指出来源事实编号的句子不得进入正文。

正文只允许以下变换：保留原文事实；删除重复、空泛或无关成分；调整已确认事实顺序；合并可分别映射到来源事实且不新增因果关系的分句；为语法完整补充主语、时间或标点。除此之外的语义扩写都先视为待确认。

原文没有出现时，不得新增目的、收益、影响、效率、能力结论、经验结论、场景、机制、方法论或因果关系。尤其不能用“具备”“积累”“支撑”“促进”“保障”“实现”“提供依据”“推动落地”等词，把已有动作包装成新的结论。

事实状态和数据口径状态分开判断。原文明示的数字或结果属于已确认原文事实，可以原样保留；缺少周期、分母、基线等属于数据口径风险，放在风险或追问中，不把解释性括号写进简历正文。只有动作、结果或归因本身由模型推断时，才标为待确认并禁止进入正文。

## 状态与处理方式

待确认事实不得进入最终简历正文，但可以进入阶段诊断、追问清单或风险清单。只要最终正文只使用已确认事实，待确认项不阻断阶段性交付。

“不建议使用”不是自动删除。处理方式如下：

| 处理方式 | 使用条件 | 记录要求 |
|---|---|---|
| 删除 | 完全不进入输出 | 写入删除记录，保留原文和原因 |
| 降级 | 保留事实但降低篇幅或强度 | 写明降级后的去向和表达边界 |
| 合并 | 与同一事实或同一能力维度合并 | 写明合并到哪条正文 |
| 移入风险清单 | 事实可能真实但不可解释 | 标出风险来源和追问 |

删除记录只记录完全移除的原文。合并、降级和移入风险清单不是删除，必须写明去向。

## 两张记录表

删除记录只记录真正从输出中移除的原文，原因从以下删除类别中选择：

1. 与目标岗位不相关
2. 已在其他位置有更具体的体现
3. 通用软话，无证据支撑
4. 基础技能，默认已具备
5. 重复信息，同一能力维度内有类似描述
6. 篇幅不足，且信息优先级低于其他模块

原文缺失清单单独记录，使用“原文即缺失，非压缩导致”这一信息状态：公司名称、职位、任职时间、教育背景、联系方式、常驻城市或项目所属信息等标准项缺失时，写明“原文未提供，无法补充”。它不能填入删除记录表。

## 年限验算

从时间线按月份计算可验证年限，与自评年限并列展示。年限验算是派生结论，不能静默把原文数字替换成计算结果。

- 重叠任职月份只计算一次；并行兼职、顾问、实习和全职经历分开说明。
- 只写年份不写月份时，标记“月份缺失”，不得假设从 1 月到 12 月。
- “至今”使用交付日期所在年月，并在结果中写明计算日期。
- 空窗期只做时间线提示，不自行补造经历。
- 不足整年的月份按“X 年 Y 个月”展示；需要概括时向下取整，并说明依据。
- 自评年限与计算年限不同，展示“原文年限 / 按时间线计算年限 / 差异原因”。

## 隐私

提醒用户在公开场景脱敏电话、住址、身份证、客户名称、未公开业务数据和内部链接。不要把用户的真实简历或个人信息写入示例、测试或公开仓库。
