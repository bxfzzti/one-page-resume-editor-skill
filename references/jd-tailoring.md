# 按 JD 定制简历

## 前提

必须同时有可读的简历和目标 JD。没有 JD 时只能做通用诊断；没有简历时只能解析 JD 和生成素材问题。

## 流程

1. 区分硬性条件、核心职责、技能、业务场景、加分项和招聘话术。
2. 提取最重要的 3–5 项要求，保留 JD 原文依据。
3. 建立证据映射：强证据、相邻证据、弱证据、无证据，并标记差距。
4. 对弱证据先追问，不用关键词补齐。
5. 调整摘要、模块顺序、篇幅和自然关键词，生成 JD 定制简历。
6. 完成正文交付前审计，再输出匹配结论、缺口、修改记录和面试追问。

## 正文交付前审计

定制版生成后逐句核对：来源事实编号；动作和对象；贡献动词；数字和结果；待确认项去向。正文只能使用事实底稿定义的改写白名单。任一项无法通过时，从正文删除或移入追问、风险清单，不交付为最终简历句子。数据口径说明放在正文之外的风险或追问中。

## 多 JD 定制协议

多个 JD 使用同一份事实底稿，事实编号在所有版本中保持一致。输出顺序为：

1. 共用事实底稿摘要
2. JD A 的核心要求、证据映射、定制策略、版本修改记录和定制版
3. JD B 的核心要求、证据映射、定制策略、版本修改记录和定制版
4. 多版本差异说明

每个 JD 独立判断证据强度，禁止把 A 岗位关键词带入 B 岗位版本。多版本之间只能调整顺序、侧重点、表达密度和自然关键词，不能改变事实状态、贡献边界和数字。

## 约束

- 多个 JD 使用同一份事实底稿，分别生成版本，不合并成万能简历。
- 定制是受控调整，不改变事实、贡献强度、数字和行业经验边界。
- 没有证据的工具、语言、市场、管理经验和行业经验不得添加。
- “匹配分”只描述当前材料与 JD 的证据覆盖，不是录用概率；缺资料的项目标为暂无法判断。
- 匹配描述优先使用“强 / 中 / 弱 / 暂无法判断”等证据等级，不使用没有评分口径的精确分数。若用户要求评分，先说明维度、权重、证据来源和不确定项。
- 如果调整幅度已经改变候选人的职业身份，停止并提示岗位匹配可能偏弱。

## 输出

1. JD 核心要求
2. 证据映射表
3. 真实缺口和风险
4. 定制策略
5. JD 定制简历
6. 版本修改记录
7. 不建议强行添加的关键词
8. 面试追问风险
