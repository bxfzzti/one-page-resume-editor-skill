# 一页纸简历网站产品设计

## 目标

把现有 `one-page-resume-editor` Skill 做成面向中文中高阶求职者的公开网站。用户可以免费完成一次完整求职简历流程，之后按具体服务项目消耗积分。网站不做会员、订阅、自动续费或复杂权益层级。

产品的核心差异不是模板数量或无依据的 ATS 分数，而是：

- 所有版本共享事实底稿。
- 不改写用户数字、公司、岗位、项目和专有名词。
- 不把参与、协同或支持升级成负责、推动或主导。
- 没有 JD 时不声称完成岗位匹配。
- 多 JD 分版本生成，不混成万能简历。
- 生成正文经过句子级来源审计。

## 用户与首版岗位范围

主要用户是 5 年以上中文中高阶求职者。首版重点支持产品、运营、用户增长、商业化、平台和电商；其他岗位使用通用事实与证据规则。

应届生、高管、学术、海外、自由职业和创业经历不伪装成已深度支持。网站可以接受这些材料，但必须显示使用通用规则或能力尚未覆盖。

## 产品形态

采用渐进式工作台。

- 第一次使用像向导：一屏只完成一个动作。
- 完成第一次任务后，逐步展开基础简历、JD 版本、事实与风险和历史结果。
- 电脑端优先；手机端保留完整功能，但使用单栏和标签切换。
- 不把后台数据结构和 Skill 术语直接暴露给小白用户。

## 首次使用流程

1. 首页直接展示四类服务，不增加营销落地页。
2. 用户选择任务。
3. 用户上传 PDF、Word，或粘贴简历文本。
4. 浏览器解析文件并展示公司、岗位、任职时间、项目和教育信息。
5. 用户确认解析结果。
6. 用户注册，首次注册自动获得 50 积分。
7. 页面显示所选服务的积分价格和交付内容。
8. 系统冻结积分。
9. 信息不足时逐个追问，单次任务最多 6 个关键问题。
10. 服务生成结构化结果并执行事实来源审计。
11. 成功后结算积分并保存版本；失败时释放冻结积分。
12. 用户编辑、导出或继续选择其他服务。
13. 结果确认后，单独询问是否贡献本次脱敏数据；同意且样本通过脱敏检查后奖励 10 积分。

游客可以上传、解析和预览材料。发生 AI 调用、积分冻结或云端保存前必须登录。

## 四类服务

### 看看简历问题

输出一句话判断、诊断维度、职业主线、前三项优势、前三项问题、经历优先级、风险和最多 6 个追问。没有 JD 时不显示岗位匹配结论。

### 整理成一页纸

输出内容版一页纸简历、压缩和删除记录、原文缺失清单和两页建议。Word/PDF 只在用户主动导出时生成。

### 按 JD 定制

输出 JD 核心要求、证据映射、真实缺口、定制策略、定制正文、版本修改记录和面试风险。多个 JD 共享事实编号并生成独立版本。

### 检查简历和准备面试

检查数字口径、贡献边界、黑话、事实来源、可能夸大和面试追问。它不是完整题库或招聘预测。

## 页面与导航

首版路由：

- `/`：四类任务入口、最近简历和积分余额。
- `/start`：任务选择、文件解析、材料确认和登录。
- `/resumes`：基础简历项目列表。
- `/resumes/:resumeId`：渐进式工作台。
- `/points`：余额、充值、积分包和完整流水。
- `/account`：账户、数据删除、隐私和数据贡献记录。

顶部主导航只显示“我的简历、积分、账户”。

## 渐进式工作台

首次任务生成前采用单栏向导，不显示完整三栏。

生成结果后，电脑端工作台逐步展开：

- 左侧：基础简历、JD 版本和历史结果。
- 中间：当前结果、修改稿和版本对比。
- 右侧：事实与风险抽屉，默认收起。

用户界面不用“事实底稿”一词，改为：

- 已确认信息
- 需要你确认
- 原文没有提供
- 不建议写入

用户点击正文中的风险标记时，右侧抽屉展开并显示来源原文、事实状态、贡献边界和追问。事实编号默认不显示，只在“查看来源”中提供。

手机端使用“流程、当前结果、事实与风险”三个标签，底部固定显示主要操作和本次积分价格。

## 内容编辑与版本

一份基础简历对应一份共享事实底稿。每次新增用户回答，先更新事实底稿，再由用户选择是否刷新相关版本。

版本类型：

- 基础内容版
- 一页纸版
- JD 定制版
- 用户手动保存的版本

系统不会静默覆盖旧版本。AI 修改以逐句建议或新版本形式产生，用户可查看原文、建议和最终采用内容。

## 积分模型

统一比例：`人民币 1 元 = 10 积分`。

没有会员、订阅、等级、自动续费或积分有效期。

### 注册赠送

- 首次注册赠送 50 积分。
- 一个账户和一个验证身份只能领取一次。
- 赠送积分永久有效。
- 优先消耗赠送积分，再消耗购买积分。

### 服务价格

| 服务 | 积分 |
|---|---:|
| 通用简历诊断 | 5 |
| 一页纸内容重构 | 15 |
| 单 JD 深度定制 | 12 |
| 双 JD 分版本定制 | 20 |
| 每增加一个 JD | 8 |
| 简历风险与面试追问 | 8 |
| 基于当前结果深度追问一轮 | 3 |
| 事实底稿 | 0，包含在服务中 |
| 基础 Word/PDF 导出 | 0 |
| 手动编辑和查看历史版本 | 0 |

### 购买积分

- 最低购买 10 积分，价格 1 元。
- 支持输入 1 至 99 元整数金额，按 1:10 到账。
- 轻量包：5 元，50 积分。
- 求职包：10 元，110 积分。
- 冲刺包：20 元，240 积分。
- 长期包：50 元，650 积分。
- 购买积分永久有效。

第一版使用测试支付。完整创建订单、模拟支付回调和积分到账，但不发生真实扣款。真实支付在测试支付和订单账本验收通过后接入。

## 积分账本

积分使用不可只维护一个可变余额。使用不可变流水记录每次赠送、购买、冻结、结算、释放、退款和数据贡献奖励。

服务执行状态：

1. `quoted`：已报价，未冻结。
2. `reserved`：已冻结积分。
3. `running`：服务执行中。
4. `succeeded`：结果通过审计并结算。
5. `failed`：服务失败并释放冻结。
6. `cancelled`：用户取消并释放冻结。

同一个服务请求使用幂等键，重试不能重复扣积分。模型超时、解析失败、空结果、结构校验失败或来源审计失败均不结算。

## 数据保存与训练贡献

用户工作数据和训练贡献数据必须分开保存、分开授权、分开访问。

### 用户工作数据

保存原始文件、解析文本、事实信息、JD、任务结果、版本和积分流水，用于提供服务和历史版本管理。用户可以删除单份简历、原始文件或整个账户。

### 数据贡献计划

- 默认不用于模型训练。
- 结果生成后逐任务询问，默认不勾选。
- 拒绝不影响服务、价格、结果质量和后续使用。
- 贡献样本通过脱敏检查后奖励 10 积分。
- 每月最多奖励 30 积分。
- 用户可以查看贡献记录并停止未来使用。

训练数据不保存原始 PDF/Word。进入训练库的内容包括：脱敏原文片段、事实状态、JD 证据映射、用户采纳或拒绝的建议、错误标签和最终确认表达。

必须删除或替换姓名、电话、邮箱、微信、住址、身份证、内部链接、真实客户名、敏感项目名、可识别个人的公司时间组合、未公开经营数据和商业秘密。敏感个人信息不进入训练库。

对外表述必须与实际行为一致：默认只用于提供当前服务；只有用户主动贡献后，脱敏任务数据才用于改进模型。

## 技术架构

网站代码放入同一仓库的 `web/`，Skill 规则继续保留在仓库根目录。Web 应用通过版本化的 Skill 加载器读取 `SKILL.md` 和对应 `references/`，不能复制出另一套漂移规则。

首版技术栈：

- Next.js App Router + TypeScript
- React 服务端组件与客户端交互组件
- Tailwind CSS + Lucide 图标
- PostgreSQL
- Drizzle ORM 与 SQL migrations
- 本地开发文件存储 + S3 兼容生产存储适配器
- 邮箱验证码登录；微信登录后续接入
- 模型提供商适配层，密钥只存在服务端
- DOCX 使用结构化文档生成库
- PDF 从同一 HTML/内容源通过无头浏览器生成并回读验证

首版采用 Next.js 全栈应用，不拆独立微服务。耗时 AI 任务通过数据库任务表和后台 worker 执行，避免请求超时。模型调用、积分账本、文件处理和训练贡献分别使用清晰服务边界。

## 核心数据对象

- `users`：用户和验证身份。
- `resume_projects`：基础简历项目。
- `source_files`：原始文件和解析状态。
- `fact_items`：事实条目、状态、来源和贡献边界。
- `job_descriptions`：目标 JD。
- `service_runs`：服务订单、价格、状态、输入快照和幂等键。
- `resume_versions`：基础、一页纸和 JD 定制版本。
- `point_ledger`：所有积分变动。
- `payment_orders`：测试或真实支付订单。
- `contribution_consents`：逐任务授权和授权版本。
- `training_samples`：脱敏后的训练样本，不含原始文件。
- `audit_events`：高风险操作和删除记录。

## 模型调用约束

- 每类服务使用结构化输出 schema。
- 输入只加载当前任务需要的 Skill 参考文件。
- 事实底稿是所有版本唯一来源。
- 生成正文后执行句子级来源和贡献边界审计。
- 审计失败时不保存为最终版本、不结算积分。
- 模型提供商可替换，但行为回归使用同一组 cases 和 expected。
- 分析日志不记录完整简历正文、联系方式或模型密钥。

## 文件处理

- 游客文件先在浏览器解析并预览。
- 登录确认后才上传原始文件和解析文本。
- 原始文件与解析文本分开存储。
- 文件下载使用短时签名链接。
- Word/PDF 生成后检查页数、可复制文本、关键字段和内容一致性。
- 一页压缩损失重要事实时，提示使用两页，不强行导出一页。

## 错误与恢复

- 文件无法解析：允许重新上传或粘贴文本，不创建收费任务。
- 信息不足：保存当前进度并追问，不结算积分。
- 模型超时：自动重试一次；仍失败则释放积分。
- 结构化输出无效：不展示为最终结果，释放积分并记录质量事件。
- 来源审计失败：结果进入内部失败记录，不交付、不扣积分。
- 网络断开：任务继续执行，用户重连后恢复状态。
- 支付回调重复：使用订单幂等键，只到账一次。
- 用户重复点击：同一服务运行只创建一个任务。

## 安全与隐私

- 所有网络请求使用 TLS。
- 数据按用户隔离，服务端检查资源所有权。
- 原始文件和训练样本使用不同存储前缀和权限。
- 模型密钥、邮件密钥和支付密钥不进入浏览器。
- 管理员读取原始简历需要审计记录。
- 删除账户时撤销会话、删除工作数据、删除未进入训练批次的贡献样本并保留必要财务流水。
- 分析埋点只记录页面、服务类型、耗时、状态和积分，不记录简历正文。

## 首版范围

首版包含：

- 四类服务入口
- PDF、Word 和文本输入
- 邮箱验证码登录
- 50 注册积分
- 测试支付与积分包
- 事实与风险
- 一页纸和单/多 JD 版本
- Word/PDF 基础导出
- 历史版本
- 数据贡献授权和模拟脱敏入库

首版不包含：

- 真实微信或支付宝扣款
- 微信登录
- 招聘平台连接或自动投递
- 岗位搜索
- 完整求职信或题库
- 人工专家服务
- 自动执行模型训练
- 企业或高校后台

## 实施阶段

### 阶段一：可用 Web MVP

完成渐进式工作台、四类服务、文件解析、邮箱登录、积分账本、注册赠送、真实模型调用、历史版本和基础导出。积分购买使用测试支付。

### 阶段二：公开测试

接入正式对象存储、邮件服务、监控、备份、隐私与删除流程。邀请真实用户使用赠送积分，观察任务完成率、失败率和积分消耗。

### 阶段三：真实收费

在具备合法收款主体、支付渠道、服务协议、隐私政策和退款规则后接入真实支付。真实支付与模型训练能力分别验收，不能一起开启。

### 阶段四：训练与角色扩展

使用用户主动贡献并完成脱敏审核的数据建立离线评测集和训练集。先验证数据质量和偏差，再决定微调或检索增强。新增岗位规则继续放入 Skill 的 `references/roles/`。

## 验收标准

### 产品流程

- 新用户不需要理解内部术语即可完成一次服务。
- 注册后准确到账 50 积分。
- 每个收费按钮在执行前显示积分价格。
- 成功任务只扣一次；失败任务不扣积分。
- 多 JD 版本共享事实编号且不混版。

### 真实性

- 不修改数字、公司、岗位、项目和贡献边界。
- 无 JD 不输出岗位匹配结论。
- 无来源结果和贡献升级不能进入正文。
- 原文缺失与压缩删除分开。

### 文件输出

- Word 可编辑。
- PDF 文本可复制。
- 页数、关键字段和内容一致性通过真实渲染验收。
- 桌面与手机均无文本重叠、溢出或不可操作控件。

### 隐私与训练

- 未授权任务不能进入训练样本。
- 拒绝贡献不影响产品使用。
- 训练样本不含原始文件和直接身份信息。
- 贡献奖励每个任务最多发放一次。
- 用户删除和撤回操作有审计记录。

### 测试

- 单元测试覆盖积分流水、幂等、授权和事实状态。
- 集成测试覆盖文件解析、模型结构化输出、任务恢复和自动退款。
- 现有 `tests/regression/` cases 通过 Web 服务入口重新执行。
- Playwright 验证首次流程、重复点击、断网恢复、移动端标签和删除账户。
- Word/PDF 使用真实生成、回读和页面截图验收。

## 成功指标

公开测试阶段只使用产品行为指标，不声称招聘成功率：

- 上传后完成材料确认的比例。
- 注册后完成首个服务的比例。
- 首个服务成功率和平均耗时。
- 赠送积分用完前完成两种服务的比例。
- 用户主动保存或导出结果的比例。
- 购买测试积分包的意向点击率。
- 数据贡献的主动选择率和脱敏通过率。
- P0 真实性失败率必须为零。

## 不做的承诺

- 不承诺录用概率或面试结果。
- 不使用无口径的精确匹配分。
- 不声称能绕过所有 ATS。
- 不把用户简历默认用于模型训练。
- 不用付费墙限制用户取回自己的基础内容和文件。
