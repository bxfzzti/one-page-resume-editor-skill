# 简历 Skill 二期可执行规则设计

## 目标

把首轮重构中的原则性规则补成可执行、可回归检查的规程，重点解决事实底稿字段、改写边界、年限派生、多 JD 版本、单页/双页判断、Word/PDF 真实渲染和角色扩展机制。

二期仍然保持当前产品定位：面向 5 年以上中高阶中文求职者，默认先交付内容，只有用户明确要求时才生成 Word/PDF。第一版深度支持产品、运营、用户增长、商业化、平台和电商；其他岗位使用通用规则，不伪装成专业深度支持。

## 背景结论

当前仓库已经完成中文入口、按任务加载参考文件、事实真实性硬规则和本机安装副本同步。审查发现首轮规则方向正确，但部分规则仍停留在原则层：

- 事实底稿没有固定字段，后续模型可能漏记来源、状态或处理去向。
- “不建议使用”“删除”“降级”“合并”的边界不够清楚。
- 年限验算没有覆盖重叠任职、只写年份、至今、兼职/实习等情况。
- 多 JD 只写了共用事实底稿和分别生成版本，没有固定输出协议。
- Word/PDF 已要求真实渲染，但没有写明验收动作和不可接受形态。
- 场景测试是行为矩阵，缺少输入片段、必须输出、禁止输出和通过标准。

## 设计方案

采用“补强现有参考文件，不引入新应用或重型自动化”的方案。二期只改 Markdown Skill 规则、示例和场景测试，不新增运行时依赖。

保留现有文件结构，并在以下文件内收敛规则：

- `references/fact-ledger.md`：事实底稿模板、处理去向、年限计算细则。
- `references/one-page-resume.md`：只重组不改义、单页压缩优先级、两页触发条件。
- `references/jd-tailoring.md`：多 JD 定制协议、匹配描述口径、版本差异记录。
- `references/document-output.md`：Word/PDF 真实渲染验收清单和失败处理。
- `references/roles/product-operations-growth.md`：重点岗位子方向、相邻证据降级表达和角色扩展规则。
- `SKILL.md` 与 `README.md`：补充角色路由和多 JD/文件交付提醒。
- `tests/scenarios.md`：升级为半可执行回归夹具。
- `examples/05-JD证据映射与受控定制.md`：补齐事实底稿摘要、定制版片段，移除无口径精确数字。

## 事实底稿规则

事实底稿必须提供标准字段：

- 原文摘录
- 来源位置
- 事实类型
- 事实状态
- 贡献边界
- 数据口径
- 处理方式
- 是否进入正文
- 风险或追问

状态规则保持四类：已确认、待确认、原文缺失、不建议使用。待确认事实不得进入最终简历，但可以进入追问或风险清单，不阻断基于已确认事实的阶段性诊断。

“不建议使用”不等于直接删除。处理方式分为删除、降级、合并、移入风险清单。删除记录只记录完全移除的原文；合并和降级必须写明去向。

年限验算按月份做派生计算，重叠任职不重复计算；只写年份不写月份时标记月份缺失；“至今”使用交付日期所在年月；兼职、顾问、实习和全职经历分开说明；展示原文年限和计算年限，不静默覆盖。

## 一页纸规则

允许的改写动作是重排、压缩、同一事实合并、语序优化和模块重组。禁止换概念、升级职责、替换不理解黑话、补造动机/方法/结果、把团队结果归给个人。

单页压缩顺序为：重复职责、泛化软话、低相关早期经历、基础技能、重复能力维度、低证据表述。不得优先删除近期核心项目、个人贡献、关键背景、可解释结果和重要能力维度。

如果只能保留“动作 + 数字”，而无法保留背景、判断、贡献或机制，应提醒使用两页。两页触发不是失败，而是保全事实和面试可解释性的结果。

不理解的黑话优先保留并追问。只有在用户确认低优先级、重复或无关，或存在更清楚的已确认事实替代时，才可删除并记录原因。

## JD 与多版本规则

单个 JD 定制必须先输出 JD 核心要求和证据映射，再生成版本。匹配描述使用“强 / 中 / 弱 / 暂无法判断”或类似等级，不使用没有口径的精确分数。

多个 JD 使用固定协议：

1. 一份共用事实底稿，事实编号在所有版本中保持一致。
2. 每个 JD 单独拆解要求和证据映射。
3. 每个 JD 单独输出定制策略、定制版本和版本修改记录。
4. 禁止把 A 岗位关键词带入 B 岗位版本。
5. 多版本之间只能调整顺序、侧重点、表达密度和自然关键词，不能改变事实状态、贡献边界和数字。

示例中不得出现无法解释的改动百分比或匹配精确分数。若确实需要评分，必须先定义评分维度、权重、证据来源和不确定项。

## Word/PDF 真实渲染

Word/PDF 是内容确认后的文件化阶段。成功标准不是文件存在，而是同版内容真实渲染通过。

可编辑 Word 的验收标准：

- 正文是可编辑文本段落、列表或表格。
- 不把整页简历做成图片。
- 不用过度碎片化文本框承载主要内容。
- 标题、任职时间、公司、岗位和联系方式可被复制。

PDF 的验收标准：

- 从同版内容导出。
- 能回读页数。
- 能抽取可复制文本。
- 首屏姓名、联系方式和核心标题可识别。
- 无明显溢出、遮挡、重叠或页脚截断。

发现文件验收失败时，必须回到内容压缩或排版调整，不把未通过文件交给用户作为最终产物。

## 角色扩展

产品、运营、增长、商业化、平台和电商使用当前深度参考。每个子方向只提供常见能力维度、证据类型和追问方向，不替用户虚构行业经验。

非重点岗位默认使用通用规则：事实提取、贡献边界、证据强度、JD 映射、风险审查和可读性优化。不得自动创造岗位专业指标、工具链或行业判断。

后续新增角色文件时，放入 `references/roles/`，并在 `SKILL.md` 中写明触发条件。多个角色都相关时，优先使用目标 JD 或用户明确目标岗位；无法判断时只用通用规则并提出追问。

## 场景测试

`tests/scenarios.md` 升级为半可执行夹具，每个场景包含：

- 输入材料摘要
- 用户请求
- 必须读取的参考文件
- 必须输出
- 禁止输出
- 风险标记
- 通过标准

新增或补强场景：

- 用户只说“帮我优化简历”，但没有 JD。
- 只有 JD，没有简历。
- 多个 JD 版本。
- 非重点岗位 JD。
- 自评年限与时间线不一致。
- 任职时间重叠。
- 只写年份不写月份。
- 原文缺失被误放入删除记录。
- 同一事实合并后含义被扩大。
- 信息严重不足。
- 频繁跳槽、短经历、空窗期、转行。
- 无数字成果。
- 明确要求 Word/PDF。
