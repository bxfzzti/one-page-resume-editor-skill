# 简历 Skill 重构设计

## 目标

把现有“一页纸简历修改器”重构为面向 5 年以上中高阶求职者的中文简历整理与岗位定制 Skill：通用覆盖各职业方向，第一版重点支持产品、运营、增长；默认先交付内容，用户明确需要时再生成并验证 Word/PDF。

## 用户与边界

- 通用适用：5 年以上中高阶求职者。
- 深度支持：产品、运营、用户增长、商业化、平台和电商岗位。
- 通用支持：技术、数据、设计、销售、市场、项目管理和职能管理。
- 后续扩展：应届生、实习生、高管、海外求职、学术、自由职业和创业经历。
- 这是可被 Codex、Claude Code 或其他智能体调用的 Skill，不是独立招聘平台或简历应用。

## 用户入口

面向用户只保留四种通俗任务：

1. 看看简历问题：诊断定位、证据、结构、时间线和经历权重。
2. 整理成一页纸简历：生成一页核心版；若保全关键事实会受损，提醒改为两页。
3. 按 JD 定制简历：拆解 JD、建立证据映射并生成岗位版本。
4. 检查简历和准备面试：检查夸大、黑话、数据口径、贡献边界并生成追问。

没有 JD 时只能做通用诊断或整理，不得声称完成岗位匹配。用户明确需要 Word/PDF 时，才进入独立排版阶段。

## 事实与真实性机制

所有输出共享一份事实底稿，每条信息标记为“已确认”“待确认”“原文缺失”或“不建议使用”。只有已确认信息能进入最终简历；估算必须保留估算属性。

- 不修改用户提供的数字、公司名、岗位名、项目名、专有名词和内部业务表述。
- 不把参与写成负责，不把协作写成主导，不把平台结果全部归给个人。
- 不理解的黑话先原样保留并追问，不自行翻译；无法确认且必须删除时记录原因。
- 删除记录与原文缺失清单分开。
- 每轮最多追问 6 个会改变结论的问题。
- 年限计算是派生结论，不能静默覆盖用户原文；存在差异时并列展示“原文年限 / 按时间线计算年限”，说明采用的结果。

## 交付物

### 通用诊断

一句话判断、维度评分、职业主线、前三项优势、前三项问题、经历优先级、缺失信息和下一步问题。评分只表示当前材料质量，不表示录用概率。

### 一页纸整理

一页核心简历、修改记录、删除记录、原文缺失清单、黑话确认清单、年限验算和面试追问风险。默认一页；重要事实无法保全时提醒两页。

### JD 定制

岗位核心要求、证据映射、真实匹配和缺口、JD 定制简历、版本修改记录、不建议强行添加的关键词和面试追问风险。基于同一事实底稿分别生成多个 JD 版本，不生成万能混合版。

### 面试与投递前审查

按核心陈述生成“负责范围、数据口径、个人贡献、协作者边界、机制和复盘”追问；标记无法解释的表述，但不因模型无法回答就自动删除用户事实。

### 按需排版

用户明确要求后，才生成可编辑 Word 和可投递 PDF，并检查实际页数、文本可复制性、标准标题、日期一致性和基本可读性。内容阶段不承诺文件排版结果。

## 任务组织

入口文件只负责任务识别、事实底稿和总规则；分任务参考文件分别负责诊断、一页纸整理、JD 定制、审查与排版。岗位深度规则单独存放，避免每次加载所有流程。

## 验收场景

必须覆盖：只有简历、只有 JD、信息严重不足、完整简历加 JD、多个 JD、单公司多年任职、频繁跳槽、短经历、空窗期、转行、无数字成果、数字无法解释、内部黑话、用户要求夸大、超出一页、Word/PDF 按需生成。

每个场景检查：是否正确识别任务、是否追问关键事实、是否保护原文、是否区分删除和缺失、是否输出可执行结果、是否标记风险，以及是否避免把通用规则伪装成岗位专业判断。

## 不纳入第一版

不实现投递平台自动操作、岗位自动搜索、投递跟踪、求职信、完整面试题库和高管/学术等专门岗位规则；这些作为后续扩展。
