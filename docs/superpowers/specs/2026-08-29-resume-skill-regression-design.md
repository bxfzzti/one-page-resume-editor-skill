# 简历 Skill 真实样例回归测试设计

## 目标

验证一页纸简历 Skill 在接近真实使用的输入下，是否能稳定执行已定义的事实底稿、任务路由、JD 定制、多版本隔离、风险审查和文件交付边界。

三期重点不是继续扩写规则，而是用回归样例检查规则是否真的可用。先用虚拟样例打通流程，再预留真实脱敏样例入口。真实个人材料只用于本地验证，不进入公开示例或公开仓库。

## 范围

本期采用半自动回归夹具：

- 构造 3 个虚拟样例，覆盖最核心用户路径。
- 预留 2 个真实脱敏样例入口，等待用户后续提供材料。
- 每个样例包含输入材料、用户请求、应读取参考文件、必须输出、禁止行为和通过标准。
- 使用独立子线程按 Skill 实跑样例，主线程回收结果并判断是否通过。

本期不做完整测试工具化，不新增自动评分器，不新增 Word/PDF 生成脚本。

## 样例集

### 虚拟样例 1：只有简历，用户说帮我优化

目的：验证没有 JD 时是否只做通用诊断，不输出岗位匹配分或定制版。

输入应包含：

- 5 年以上经历。
- 至少一段职责流水账。
- 至少一条数字但口径不完整。
- 至少一个内部黑话。
- 缺少目标 JD。

必须验证：

- 输出当前是通用诊断，不是岗位定制。
- 给出定位、前三项问题、经历优先级、缺失信息和追问。
- 不输出岗位匹配分、录用概率或 JD 定制版。

### 虚拟样例 2：简历加单个 JD

目的：验证 JD 定制是否先做证据映射，再生成受控版本。

输入应包含：

- 产品、运营或增长方向简历。
- 一个明确 JD。
- 强证据、相邻证据、弱证据和无证据要求。
- 一处可能被夸大的贡献边界。

必须验证：

- 输出 JD 核心要求和证据映射。
- 弱证据先追问，无证据关键词不进入正文。
- 定制版只调整顺序、侧重点、表达密度和自然关键词。
- 不改变数字、贡献边界、行业经验和事实状态。

### 虚拟样例 3：简历加多个 JD

目的：验证多 JD 是否共用事实底稿、分别映射、版本隔离。

输入应包含：

- 同一份候选人简历。
- 两个目标 JD：一个偏用户增长，一个偏平台产品或商业化。
- 可被两个 JD 共同使用的事实。
- 只适合其中一个 JD 的关键词。

必须验证：

- 输出共用事实底稿摘要。
- 每个 JD 独立拆解要求、证据映射、定制策略和版本修改记录。
- 两个版本共享事实编号。
- 不生成万能混合版，不把 A 岗位关键词带入 B 岗位版本。

### 真实脱敏样例入口

预留 2 个本地样例入口：

- 真实样例 A：用户提供脱敏简历，可无 JD，用于验证诊断和一页纸整理。
- 真实样例 B：用户提供脱敏简历和 JD，用于验证岗位定制和面试风险。

真实样例必须先脱敏：

- 电话、邮箱、住址、身份证、微信号、内部链接全部移除或替换。
- 公司名、客户名、产品名、项目名如有敏感性，替换为稳定代号。
- 未公开业务数据保留口径但改写为区间或相对描述，除非用户明确允许保留。
- 脱敏映射表不提交到 GitHub。

## 文件组织

建议新增目录：

```text
tests/regression/
├── README.md
├── cases/
│   ├── 01-general-diagnosis.md
│   ├── 02-single-jd-tailoring.md
│   └── 03-multi-jd-tailoring.md
├── expected/
│   ├── 01-general-diagnosis.md
│   ├── 02-single-jd-tailoring.md
│   └── 03-multi-jd-tailoring.md
└── results/
    └── .gitkeep
```

`cases/` 保存虚拟输入材料和用户请求。`expected/` 保存必须输出、禁止输出和通过标准。`results/` 保存独立子线程实跑摘要；如果包含真实脱敏材料的输出，则只保留本地，不提交。

真实脱敏样例默认放在本地未跟踪目录：

```text
tests/regression/local-private/
```

该目录应加入 `.gitignore`，防止真实材料进入公开仓库。

## 回归执行方式

每个虚拟样例使用一个独立子线程执行：

1. 主线程分派样例输入和期望标准。
2. 子线程必须读取当前仓库中的 Skill 文件和相关参考文件。
3. 子线程按用户请求生成实际输出摘要。
4. 子线程对照 expected 自评通过、失败或部分通过。
5. 主线程复核结果，记录最终判断。

子线程只执行样例，不修改 Skill 规则。若发现规则缺口，子线程只报告问题，由主线程决定是否进入新一轮设计。

## 通过标准

三期通过需要满足：

- 3 个虚拟样例都有可读输入和 expected 文件。
- 3 个虚拟样例均完成独立子线程实跑。
- 主线程记录每个样例的通过状态、问题和对应规则文件。
- 没有发现 P0 级问题：编造事实、无 JD 输出匹配、改数字、升级贡献边界、多 JD 混版、真实材料入库。
- 如果有 P1/P2 问题，记录到回归结果中，并明确是否需要四期修复。

## 失败分级

- P0：违反真实性底线或隐私底线，包括编造事实、修改数字、升级贡献、泄露真实材料、无 JD 输出匹配结论。
- P1：核心流程缺失，包括未建事实底稿、未做证据映射、多 JD 未隔离、Word/PDF 未验收却声称完成。
- P2：输出可用性问题，包括结构不清、追问过多、缺少修改记录、风险表述不够具体。

P0 必须先修复再继续验证。P1 可以进入修复计划。P2 可以记录为后续优化。

## 不做范围

本期不把真实简历提交到公开仓库，不做自动评分器，不做招聘平台连接，不做 Word/PDF 模板生成，不扩展新岗位深度规则。
