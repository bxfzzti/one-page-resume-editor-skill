# 简历正文句子级来源门禁设计

## 背景

三期真实样例回归发现，模型虽然保留了原文数字和主要贡献动词，仍会在定制正文中补出原文未证明的结果或扩大贡献强度：

- Case 02 把“活动 SOP 支持 12 个城市复用”扩写为“提升跨城市活动执行的一致性和复用效率”。
- Case 03 把“协同产品团队上线”扩写为“推动平台工具与运营机制落地”。

这两类表达分别构成未确认结果和贡献升级，属于 P0。现有规则规定事实底稿状态和贡献边界，但缺少正文生成后的句子级核对动作。

## 目标

在不增加自动评分器或复杂工具的前提下，确保最终简历正文中的每个动作、对象、贡献动词和结果都能追溯到已确认事实。

## 方案

采用“事实底稿来源门禁 + JD 正文交付前审计”。

### 事实底稿来源门禁

每条候选正文必须标注对应事实编号。句子中的动作、对象、贡献边界和结果分别核对：

- 原文明确支持或用户明确确认的内容可以进入正文。
- 只由常识或语言润色推导出的收益、效率、影响、机制、能力结论不能作为已确认事实。
- “提升效率”“提高一致性”“提供数据依据”“推动机制落地”等新增结果性表达，原文没有对应证据时必须删除或移入待确认。
- 贡献动词只能保持原强度或降级，不能把“参与、协同、支持”改成“推动、牵头、负责、主导”。

### 正文改写白名单

句子级核对不能只依赖原则判断。最终正文只允许以下变换：

- 保留原文动作、对象、贡献动词、数字和结果。
- 删除重复、空泛或与目标岗位无关的成分。
- 调整已确认事实的顺序。
- 合并指向同一能力维度的事实，但每个分句都能映射到来源事实，且不新增因果关系。
- 为语法完整补充主语、时间或连接标点，但不能补充新的业务含义。

原文没有出现时，不得新增目的、收益、影响、效率、能力结论、经验结论、场景、机制、方法论或因果关系。尤其不能用“具备”“积累”“支撑”“促进”“保障”“实现”“提供依据”“推动落地”等词把动作包装成新结论。

事实状态和数据口径状态分开判断。原文明示的数字或结果属于已确认原文事实，可以原样保留；缺少周期、分母、基线等属于数据口径风险，放在风险或追问中，不把解释性括号写进简历正文。只有动作、结果或归因本身由模型推断时，才标为待确认并禁止进入正文。

### JD 正文交付前审计

定制版生成后，逐句检查：

1. 该句对应哪些事实编号。
2. 动作和对象是否在原文中存在。
3. 贡献动词是否保持或降低强度。
4. 数字和结果是否原文支持，数据口径风险是否另行提示。
5. 无法通过核对的内容是否已从正文移入追问或风险清单。

待确认事实可以出现在事实底稿、证据映射、追问和风险提示中，但不能因为加了括号说明就进入最终简历正文。数据口径风险也应与简历正文分开呈现。

## 文件范围

- 修改 `references/fact-ledger.md`，加入句子级来源门禁。
- 修改 `references/jd-tailoring.md`，加入正文交付前审计。
- 修改 Case 02 和 Case 03 的 expected，明确禁止回归中出现的两类表达。
- 不修改 `SKILL.md`，入口已明确要求读取上述参考文件。
- 不新增脚本，不扩展岗位规则，不改变用户任务路由。

## 验证

使用原 Case 02 和 Case 03 重新派发独立子线程：

- Case 02 不得新增“提升跨城市活动执行的一致性和复用效率”等无来源结果。
- Case 03 不得把“协同产品团队上线”改成“推动平台工具与运营机制落地”。
- 两案正文不得新增原文没有的目的、收益、能力结论、经验结论、场景、机制或因果关系。
- 两案仍需满足原 expected 的全部必需项和禁止项。

若复测仍出现编造结果、贡献升级或待确认内容进入最终正文，继续判为 P0，不提交三期实现。
