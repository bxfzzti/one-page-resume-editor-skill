# 示例 06 — 单公司多年经历如何按能力维度拆分

## 场景

候选人在同一家公司工作 4 年，经历了多个项目：

- 会员增长
- 首页流量分发
- 活动工具建设
- 跨部门需求管理
- 商家资源协同

如果只按公司写成一个大段落，简历会显得又长又散；如果为了压缩直接删项目，又会损失能力宽度。

## 有风险的压缩方式

```text
### 2020.03—2024.06｜某平台｜高级运营

负责平台运营、会员增长、活动运营、资源协调和需求管理，推动用户活跃、转化和业务增长。
```

## 更好的写法

```text
### 2020.03—2024.06｜某平台｜高级运营

**用户增长：** 围绕会员拉新、权益触达和留存提升搭建增长机制，设计会员频道、等级权益及活动承接链路，推动核心用户活跃与转化提升。

**流量效率：** 负责首页及频道流量运营，基于用户分层、场景入口和活动节奏优化资源分配，提高关键入口点击、承接效率和转化表现。

**系统化建设：** 梳理活动配置、权益发放、数据复盘等重复流程，沉淀可复用模板和协作规范，降低跨团队沟通成本并提升活动上线效率。

**需求管理：** 对接产品、技术、行业和商家团队，拆解业务诉求、排定优先级并推动落地，保证核心项目在资源受限情况下按期交付。
```

## 信息保全清单

| 原始项目 | 压缩后对应表达 | 状态 | 原因 |
|---|---|---|---|
| 会员增长 | 用户增长 | 保留 | 核心能力维度 |
| 首页流量分发 | 流量效率 | 保留 | 独立能力维度 |
| 活动工具建设 | 系统化建设 | 保留 | 体现机制沉淀 |
| 跨部门需求管理 | 需求管理 | 保留 | 体现推进复杂度 |
| 商家资源协同 | 用户增长 / 需求管理 | 合并 | 作为机制证据保留，不单独展开 |

## 规则

单公司长期任职不等于只有一段经历。压缩时先按能力维度分组，再在同一维度内删除重复内容；不要跨维度删减，否则会把真实经历压窄。
